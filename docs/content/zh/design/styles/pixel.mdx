# 像素风格

同一个角色，画在网格上。所有状态、形状和脸（包括默认的 `cute` 脸和周围的特效）在像素系列里都能用：它读取的帧与 vector 系列相同，只决定填哪些格子。

```tsx preview
import { CharacterMark } from '@aora-bot/react';

export default function Demo() {
  return (
    <div className="site-demo">
      {['blob', 'hex', 'cloud', 'star'].map((shape) => (
        <CharacterMark key={shape} styleId="pixel" shape={shape} color="blue" state="happy" sizePx={96} />
      ))}
    </div>
  );
}
```

```tsx
<CharacterMark styleId="pixel" shape="blob" />
<CharacterMark styleId="pixel" variant="dot" styleOptions={{ grid: 32 }} />
```

默认系列是 `vector`，没有指定画风的角色用它来画。

## 变体

```tsx preview
import { CharacterMark } from '@aora-bot/react';

const variants = ['crisp', 'dot', 'block'] as const;

export default function Demo() {
  return (
    <div className="site-demo">
      {variants.map((variant) => (
        <div className="site-demo__cell" key={variant}>
          <CharacterMark
            styleId="pixel"
            variant={variant}
            shape="blob"
            color="orange"
            state="curious"
            sizePx={110}
          />
          <span className="site-demo__label">{variant}</span>
        </div>
      ))}
    </div>
  );
}
```

| 变体    | 画法                                                                   |
| ------- | ---------------------------------------------------------------------- |
| `crisp` | 实心方块，默认值。相邻同色格子合并成一条边缘锐利的路径。               |
| `dot`   | LED 面板：深色底板上是暗淡的未点亮圆点，角色所在处是亮点，带一点辉光。 |
| `block` | 格子之间留有缝隙的方块，即使颜色是平的也能看出网格。                   |

`dot` 的底板是画面的一部分，不跟随主题。LED 面板在浅色页面上也是深色的，所以无论页面深浅，角色都用深色页面下的墨色点亮：`black` 亮成白色，`night` 这类近黑色会被提亮到看得见为止。眼睛默认是白色 LED，可用 `eyeColor` 指定；身体亮成浅色时，眼睛是底板颜色的未点亮圆点。

## 参数

参数放在 `styleOptions` 里。引擎把它们合并到默认值上，数值限制在范围内并对齐到步长，所以滑块和手动输入的值一致。未知的键会被丢弃。

| 参数      | 默认值 | 范围     | 含义                                                  |
| --------- | ------ | -------- | ----------------------------------------------------- |
| `grid`    | `24`   | 8 到 64  | 角色横向占的格数，相对 shape space，不是像素。        |
| `gap`     | `0.16` | 0 到 0.5 | 格子之间的缝隙，占一格的比例，`block` 和 `dot` 读取。 |
| `shades`  | `3`    | 1 到 5   | 明暗的阶数，`1` 为纯平。                              |
| `fps`     | `12`   | 0 到 60  | 运动按这个帧率采样，`0` 表示逐帧跟随。                |
| `outline` | `true` | 开或关   | 把身体边缘的格子压暗。                                |
| `glow`    | `true` | 开或关   | 亮点背后的模糊光晕，仅 `dot` 读取。                   |

选中一个变体后，面板只列出该变体读取的参数。面板由注册表生成，因此与上表一致。

```tsx preview
import { CharacterMark } from '@aora-bot/react';

const grids = [12, 16, 24, 32, 48] as const;

export default function Demo() {
  return (
    <div className="site-demo">
      {grids.map((grid) => (
        <div className="site-demo__cell" key={grid}>
          <CharacterMark
            styleId="pixel"
            shape="tofu"
            color="violet"
            state="idle"
            sizePx={96}
            styleOptions={{ grid }}
          />
          <span className="site-demo__label">grid {grid}</span>
        </div>
      ))}
    </div>
  );
}
```

`grid` 以 shape space 为单位，所以格子数不随 `sizePx` 变化。16 px 和 120 px 的标记是同一个像素角色的两种尺寸，不是两幅不同的画。

画风参数从不影响模拟。同一个 `seed` 在所有系列里眨眼的时机都相同，改 `grid` 也不会让任何动画重新开始。

## 一个格子怎么定

网格是铺在 shape space 上的固定点阵，以中心为锚点，所以对称的形状无论格数是奇数还是偶数，栅格化后都保持对称。每一帧按画家顺序栅格化到一块小缓冲区里，缓冲区存的是 paint id：

1. 腰带的环和后层拖尾，以及特效里描边的弧和环。
2. 身体：用每个格子的中心点与轮廓比对。
3. 脸：先是眼睛，再是 `cute` 脸的嘴和腮红，或线条脸的鼻子和嘴，最后是徽标。
4. 腰带的点和字形、特效的点和铅笔字形、HUD 图元、前层拖尾和粒子。

缓冲区里不存颜色。一个 paint id 代表一种色调加一个不透明度，所以判断画面有没有变化，只需比较两个整数数组。live 渲染器每收到一帧都会栅格化并比较，只有某个格子不同时才构建并写入 DOM。

### 低分辨率下的眼睛

画面只有几十格宽时，眼睛受影响最大，所以眼睛不按身体的方式采样。

- 两只眼睛按子格覆盖率测量，再与另一只眼睛的镜像取平均，合成一个字形，在左右两侧各印一次，所以天然左右对称。
- 阈值根据字形的最佳覆盖率自适应调整。闭眼这样的细笔画退回到每列一格，所以不会消失，也不会变成两行。
- 眼睛不会为空，两只眼睛之间至少隔一格。
- 线条脸的鼻子和嘴与眼睛之间、鼻子与嘴之间，各留一格空隙。

### 明暗

`shades` 选择一组色调阶梯。每个格子根据邻居分为三类：在边缘上、在左上侧受光，或在右下侧的阴影里。

| `shades` | 色调                     |
| -------- | ------------------------ |
| 1        | 纯平。                   |
| 2        | 边缘更暗。               |
| 3        | 边缘更暗，左上更亮。     |
| 4        | 同 3，右下加一层阴影。   |
| 5        | 同 4，左上再加一点高光。 |

`dot` 省掉边缘和阴影这两档暗色调，因为它们会融进底板。亮色调保留，其余的质感由辉光提供。

渐变 `ink` 会按格子位置沿渐变角度量化成 `shades` 条色带。这不会引入新的颜色 id：每一阶都是 ink 与黑色或白色的 `color-mix`，所以角色仍然跟随主题和调色板。

## 在引擎里

```ts
import { createCharacter, renderStaticSvg } from '@aora-bot/engine';

const mark = createCharacter(host, {
  style: 'pixel',
  variant: 'dot',
  styleOptions: { grid: 32 },
});

// 之后切换系列：换掉 renderer，不换模拟。
mark.update({ style: 'vector' });

const svg = renderStaticSvg({ style: 'pixel', shape: 'hex', state: 'thinking' });
```

静态输出是确定的，也不需要 DOM，可以用于服务端渲染。live 和 static 共用同一套场景构建。

系列没有的变体会回落到默认变体，所以把使用 `outline` 的 `vector` 角色切到 `pixel`，画出来的是 `crisp`。

## 在 React 里

`CharacterMark`、`CharacterMarkMirror` 和 `StagedMark` 接受 `styleId`、`variant` 和 `styleOptions`，并在根元素上输出 `data-style` 和 `data-variant`。prop 取名 `styleId`，是因为 `style` 在这些组件上已经用于内联 CSS。

`AppearanceProvider` 为整棵子树统一设置这三个 prop。标记自己的 prop 优先，嵌套的 Provider 按字段逐项合并。

```tsx
import { AppearanceProvider, CharacterMark, StagedMark } from '@aora-bot/react';

<AppearanceProvider styleId="pixel" variant="block" styleOptions={{ grid: 20 }}>
  <CharacterMark shape="blob" />
  <StagedMark shape="hex" />
</AppearanceProvider>;
```

外观相同的标记，`StagedMark` 让它们共用一个运行中的引擎。画风、变体和与默认值不同的参数都计入外观，所以像素的源不会被 vector 标记镜像，而 `{}` 与 `{ grid: 24 }` 共用同一个源。

## 限制

- HUD 表盘上的刻度数字不会绘制，在网格上太小，读不清；表盘本身会绘制。
- 半透明量化到四分之一档，会替换其下的格子，不与之混合。
- 网格较小时，有些眼睛之间的差别很细微：24 格下，开心、难过和睡着的眼睛各自只差一两行。
