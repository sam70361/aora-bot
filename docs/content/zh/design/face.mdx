# 五官

脸属于角色，而不属于某种画风。一共有十六种脸：`cute`、`eyes`、`line` 三种基础脸，加上十三种[手绘脸](#手绘脸)。它们在向量、像素、颜文字、字符画各系列里都能绘制，共用同一套状态、姿态和眨眼。默认脸是 `cute`。

<CharacterMark shape="mochi" face="eyes" />

| `face`         | 画法                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------- |
| `cute`（默认） | 圆点眼、小嘴、粉色腮红，涂在身体上；部分状态还会带出情绪特效。见[表情](/design/expressions)。 |
| `eyes`         | 两只大眼睛，剩下的交给轮廓。                                                                  |
| `line`         | 在眼睛之外加上鼻子和嘴，全部是同一线宽的笔画。                                                |

默认是 `cute`。传 `face="eyes"` 或 `face="line"` 选另外两种基础脸，传手绘脸的 id 则选[手绘脸](#手绘脸)。`eyes` 和 `line` 有各自的几何和眼型表。运行中切换 `face` 不会跳变：`cute` 与另外两种脸之间由 `cuteBlend` 弹簧过渡。

## 手绘脸

`DRAWN_FACE_STYLES` 里的十三种脸属于 cute 一族：沿用 cute 脸的点半径、眼线、腮红和情绪特效，腰带状态下身体也同样保持完整。区别在于，眼睛由若干层轮廓叠成，每层带一个颜色角色：眼白、瞳孔、眼皮、眉毛、镜片、屏幕、符号。每种脸也都是完整的一套：每个状态都有自己的眼型，有自己的嘴型表（或明确写出沿用 cute 的嘴型表），有自己的布局、眨眼和视线，还有自己的像素和颜文字画法。

### 一张设计表

每种手绘脸是 `face/drawn/designs/<id>.ts` 里的一个 `FaceDesign`：

- `layout`：布局，以 cute 点半径为单位，从 cute 眼线量起，包括抬高量、眼距、嘴的位置、嘴的缩放与线宽、腮红位置，以及视线中多少用于移动整只眼睛、多少留给瞳孔。
- `expressions`：表情，每个表情是一组数字。cute 的 19 个表情名，每种脸都有自己的画法，所以状态表可以按名字共用；屏幕脸和符号脸另有各自的表情（加载圈、放大镜……）。
- `states`、`mouths`、`stateMouth`：各状态的表情序列和嘴型。沿用 cute 的表时直接写 `states: STATE_CUTE_EYES`、`mouths: CUTE_MOUTHS`；屏幕脸和符号脸在 cute 序列的基础上覆盖忙碌状态，大嘴脸则为 cute 不画嘴的状态补上嘴。
- `mouthPaint`、`quietFx`、`kaomoji`：嘴用哪个颜色角色绘制、眼睛已经表达了哪些特效（水汪眼自己会流泪，所以不再需要 `tear`），以及文字版的眼睛和嘴。
- `eye`（以及可选的 `plate`、`inMouth`）：把一组数字变成图层。

表情之间按字段插值，所以状态切换时，部件会逐渐长出或淡入，不会突然出现。眨眼是合上眼皮还是压扁眼睛，由各种脸自己决定。

### 颜色角色

图层带的是颜色角色，不是具体颜色。`face` 是脸色（眼白）；`pupil` 是在脸色上看得清的颜色；`feature` 是在身体上看得清的颜色，用于眉毛、睫毛和直接画在身体上的眼睛，也就是 cute 脸的颜色；`glint` 是在 `feature` 上看得清的高光；`iris` 是加深后的身体墨色；其余是固定的强调色（金色星星、泪滴、舌头、爱心、怒气、纽扣的线和底色、深色玻璃）和屏幕的发光色。对于中间色相以外的颜色，`getInkVars` 还会按脸的配色规则写入 `--aora-face-pupil` 和 `--aora-face-glint`；它们随页面变化时（例如 `black`），静态输出也会随配色方案切换。

### 四个系列

- 向量：每个变体决定各颜色角色用什么颜料。实心类变体里，眼白是脸色。`outline`、`glass`、`pencil`、`neon`、`chalk` 这几个线条变体里，所有角色都用线色或页面色，眼白、镜片和屏幕另加一圈描边；把特效画成单色的变体，强调色也换成线色。riso 的错版、paper 的投影、sticker 的纸边照常作用在身体上。
- 像素：每层按覆盖率栅格化，要么整层画出，要么不画。两只眼用同一个镜像投影、在对称的锚点上栅格化，所以对称的表情会精确对称到格子，而单眼眨眼、斜视和单侧的眼泪仍保留左右差别。比一格还小的高光直接省略，以免在瞳孔上打出一个洞。
- 颜文字：每种脸有自己的眼睛字形，按 11 种眼型各写一个。状态的眼睛取序列里的第一个表情，嘴取该状态的嘴。
- 字符画：复用像素栅格器的图层，只是栅格更细，所以手绘脸的眼睛和嘴都能保留。每个 2×4 的子格合成一个字符。

### 窄的身体

设计稿按自己的尺寸绘制。放到身体上之前，先量出所有固定部件的外廓，包括眉毛、镜框、面罩、符号和嘴的宽度，再经过头部的投影检查它们落在身体上的位置：每一段都必须在身体对应高度的宽度之内，并位于头发和盖在头顶的叶子之下。放不下时，脸沿着一条路径同时缩小（最多缩到 0.45 倍）并下移（最多 1.6 个点半径），用二分法找到刚好放得下的位置；嘴和腮红随之移动。离开脸的部件（滑落的眼泪、升起的 Z）不计入外廓。身体放得下时，脸保持设计尺寸。

### 自己的脸

`defineFace(design, { label })` 以 `design.id` 为名注册你自己的 `FaceDesign`。注册后，凡是接受 `face` 的地方都能使用它，各画风系列都能绘制；它第一次画到某个身体上时，会自动适配这个身体。`FACE_KIT` 提供内置手绘脸所用的工具：眼睛的轮廓和色带、把 cute 表情转换成设计参数的方法，以及 cute 脸的表（`STATE_CUTE_EYES`、`CUTE_MOUTHS`），可以直接引用，不必复制。`cute`、`eyes`、`line` 和内置手绘脸不能被替换。

## cute：默认的脸

`cute` 脸直接涂在身体上，和 `eyes`、`line` 脸一样使用五官色 `--aora-face-soft`（大多数色相上是深色，深色墨上是白色，见[配色](/design/palette#脸的配色规则)）。每个状态各有一组眼型、嘴型和腮红，眼型按一定间隔轮换。所有表和演示在[表情](/design/expressions)，各状态的情绪特效和活动特效在[状态](/design/states)。

在 `cute` 脸下，腰带状态不会把身体缩成一个小圆点：整个角色连同脸都保留，其他脸下由腰带表达的含义，改由身旁的特效表达。

## 线条脸

`line` 脸在 `eyes` 脸的基础上加了鼻子和嘴。下面几节依次讲它如何保持一种墨、一种线宽，嘴和鼻子各是什么，以及它们怎样随状态变化。

## 一种墨，一种线宽

`eyes` 脸成立，是因为它只有一个视觉概念：一个实心身体，加两个挖出来的眼睛。再加上鼻子和嘴，就可能变成一幅混着好几种线条的画。线条脸靠下面几条规则来避免这一点：

- 每个五官都是一道与眼睛同色的笔画：`solid` 上是背景色，`outline` 和 `glass` 上是墨色。
- 所有笔画线宽相同，等于 `LINE_WEIGHT` 乘以眼睛半径，因此和眼睛一样随身体缩放。
- 眼睛向圆点的比例收缩（`LINE_FACE_TUNE`），让三个五官共用一块脸盘而不显拥挤；较细的表情（`closed`、`happy`、`sleepy`）加粗到线宽的下限，所以看起来和嘴是同一种笔画。
- 没有眉毛、腮红，也没有第二种颜色。

<LineExpressionGrid />

`eyes` 脸的全部眼睛拓扑在线条脸里都能用，线条脸只改变它们的尺寸和线宽下限。`wink` 是唯一两只眼睛不同的拓扑：一边是开心的弧，另一边是中性的眼。

## 嘴是六个数字

```ts
interface MouthSpec {
  width: number; // 半宽，单位为眼睛半径
  bend: number; // 唇线的弯曲；正数微笑，负数下撇
  open: number; // 张开的高度；0 是一条闭合的线
  wave: number; // 沿唇线的一个正弦波纹，表示不安
  skew: number; // 把顶点推向一侧嘴角，−1..1
  dy: number; // 相对静止位置的竖直偏移
}
```

唇线是穿过两个嘴角的一条抛物线，`bend` 决定它的弯曲程度，`skew` 把顶点推向一侧，再叠加一个振幅为 `wave` 的波纹。张开的部分是一个上下不对称的透镜形：下唇下落得比上唇上抬得多，真实的嘴就是这样张开的。`open` 为 0 时上下唇重合，只剩笔画可见，所以从闭嘴张成 "o" 是连续变化的形状，而不是替换。

<MouthGrid />

<MouthTable />

嘴和眼睛一样用参数表示，原因也是**形变**。每个字段独立插值，每个中间值都是合法的嘴，所以状态切换时，嘴由弹簧带着从 `frown` 缓缓变到 `grin`，而不是在两个轮廓之间硬切。

```ts
morphMouth(MOUTHS.frown, MOUTHS.grin, t); // 永远是一张嘴
```

## 鼻子只选一次

鼻子不属于表情，而是角色的特征，和形状一样，所以每个角色只选一次，眼睛和嘴变化时它保持不动。

<NoseGrid />

共六条折线。每条都是沿鼻梁向下的一道开放笔画，末端有一个小转折作鼻尖，以眼睛半径为单位存成 16 个点。传 `nose={null}` 则不画鼻子，得到只有眼睛和嘴的素线条脸。

没有指定鼻子时，会像形状和墨色一样，从角色的 key 推导出一个：`autoNoseForKey('agent-42')` 的结果是稳定的，并且把 key 均匀分到六种鼻子上。`AgentPortrait` 用的就是它，所以每个智能体都有固定的鼻子，不需要另外存储。

## 每个状态都有一张嘴

`STATE_MOUTH` 为每个状态指定一张嘴，方式和 `STATE_EYE_TOPOLOGIES` 指定眼睛相同。表情大部分已由眼睛承担，嘴只需与眼睛保持一致，例如 `sad` 下撇、`surprised` 张成 "o"、`confused` 画波浪线，不必另表一层意思。

<LineStateGrid />

有两张嘴是专门为其余十一张嘴都表达不准的状态设的。`hum` 的嘴是闭着的，神情满足，唇线上有一道波纹。若用微笑，表达的是「高兴」，而 `humming` 的要点是嘴闭着，却仍有声音发出。它刻意做得较窄，在 16 像素下不会被看成咧嘴笑。`tight` 是紧抿的嘴：短、平，比 `flat` 略低一点。`suspicious` 用它而不用 `smirk`，因为怀疑时嘴是闭紧的，由眼睛表示疑问；而斜笑配上眯起的眼睛，看起来更像觉得好笑。`refusing` 仍用下撇的嘴，因为它表示拒绝，而不只是有所保留。

有六个状态会说话：`composing`、`dictating`、`messaging`、`sending`、`laughing` 和 `humming`。它们的嘴按两个周期互不成整数比的正弦波一开一合，看起来像在说话，而不是节拍器。启用 `prefers-reduced-motion` 时不再脉动。

## 一块脸盘

鼻子和嘴用与眼睛相同的姿态矩阵投影，并按比例跟随同一个视线偏移：鼻子 60%，嘴 50%。转头时，整张脸作为一个整体被压缩；侧目时，五官一起倾斜。没有这一步，就会变成眼睛摆动而嘴留在原地，看起来像一张面具在球上滑动。

<LineShapeRow />

鼻子和嘴都会被限制在各自高度处的轮廓之内，在矮胖的身体上还会被托在下巴之上，所以 `tofu`、`onigiri` 得到的是一张完整放得下的脸，不会有五官挂到底边之外。

## 实时切换

已挂载的角色可以随时改变 `face`。眼睛尺寸、笔画下限和五官透明度都由同一个 `lineBlend` 弹簧缓动，所以嘴会随眼睛收缩而淡入，而不是一切同时跳变。改变 `nose` 时，旧鼻子淡出，新鼻子淡入。切换到手绘脸或从手绘脸切走，用的是 `faceFade` 弹簧：离开的脸保持切换那一刻的样子淡出，新的脸淡入；切回 `cute` 时，一直在底下运行的 cute 眼睛接管整张脸。

```tsx preview
import { useState } from 'react';
import { CharacterMark, FACE_STYLES, NOSE_IDS } from '@aora-bot/react';

export default function Demo() {
  const [face, setFace] = useState(0);
  const [nose, setNose] = useState(0);
  return (
    <div className="site-demo site-demo--center">
      <CharacterMark
        shape="pear"
        color="green"
        state="happy"
        face={FACE_STYLES[face]}
        nose={NOSE_IDS[nose]}
        sizePx={130}
      />
      <div className="site-controls">
        <button className="site-btn" onClick={() => setFace((f) => (f + 1) % FACE_STYLES.length)}>
          face: {FACE_STYLES[face]}
        </button>
        <button className="site-btn" onClick={() => setNose((n) => (n + 1) % NOSE_IDS.length)}>
          nose: {NOSE_IDS[nose]}
        </button>
      </div>
    </div>
  );
}
```

## 适用范围

所有绘制角色的组件都接受 `face` 和 `nose`：[`CharacterMark`](/components/character-mark)、`StagedMark`、[`AgentPortrait`](/components/agent-portrait)（也可通过智能体对象和阵容预设传入）、[`AvatarGroup`](/components/avatar-group) 以及静态渲染函数。带 `onSelectFace` 的 [`CharacterSelector`](/components/character-selector) 会显示脸型切换，线条脸激活时再多显示一行鼻子。

在[共享舞台](/components/character-stage)上，脸型和鼻子都是外观 key 的一部分。因此，同为 `line` 脸的 `blob`，鼻子是 `hook` 还是 `bow` 会算作两个源；而两个 `cute` 脸的 `blob`，鼻子不同也算同一个源。只有线条脸会画鼻子，其他脸上的鼻子没有作用，所以不会拆分舞台。

## 线条脸在各个面上

所有把角色放进某个界面的组件，包括 [`HudPlate`](/components/hud-plate) 与 [`AgentHud`](/components/agent-hud)、[编辑器](/components/avatar-studio)及其触发器、[模板对话框](/components/template-dialog)与分享卡、[`OccupancyList`](/components/occupancy-list)、[受限场景](/components/restricted-scene)与[启动序列](/components/boot-loop)、[`CastLineup`](/components/cast-lineup) 及其成员、[引导页组件](/components/walkthrough)，以及两个[选择器](/components/agent-character-selector)，都接受 `face`、`nose` 和 `lineWeight`，并原样向下传递。角色列表里那只带 `hook` 鼻子的线条脸 `bun`，在编辑器预览、分享卡和启动序列里仍是同一只。

`lineWeight` 是第三个特征，和鼻子一样，每个角色只选一次。它是 `LINE_WEIGHT` 的倍数，限制在 `LINE_WEIGHT_RANGE`（0.8–1.25）之内。这一个数字会同时作用于鼻子、嘴**和 HUD 表盘**：身体外那圈环的描边线宽与身体内的五官一致，脸和表盘看起来是同一幅画，而不是脸旁边摆着一张图表。范围定得很窄，是有意的：线宽是决定角色看起来像钢笔画还是马克笔画的唯一数字，如果让宿主随意设置，列表里就会出现线宽与邻居不同的角色，整套风格就乱了。

```tsx preview
import { CharacterMark, HudPlate } from '@aora-bot/react';

export default function Demo() {
  return (
    <div className="site-demo">
      {[0.8, 1, 1.25].map((weight) => (
        <HudPlate key={weight} title="lineWeight" value={String(weight)}>
          <CharacterMark
            shape="bun"
            color="orange"
            state="working"
            face="line"
            nose="hook"
            lineWeight={weight}
            hud={{ kind: 'progress', value: 0.65 }}
            sizePx={88}
          />
        </HudPlate>
      ))}
    </div>
  );
}
```

[`CharacterSelector`](/components/character-selector) 也接受 `lineWeight`，所以网格里的预览与正在编辑的角色用同样粗细的线条绘制。
