# AvatarStudio

在同一个对话框里选角色、生成图片或上传图片。

```tsx preview
import { useState } from 'react';
import { AvatarField, type AvatarDraft } from '@aora-bot/react';

export default function Demo() {
  const [avatar, setAvatar] = useState<AvatarDraft>({ shape: 'hex', color: 'blue', pictureUrl: null });
  return (
    <div className="site-demo site-demo--column">
      <AvatarField value={avatar} onCommit={setAvatar} />
      <span className="site-demo__label">
        {avatar.pictureUrl ? '图片' : `${avatar.shape}、${avatar.color}`}
      </span>
    </div>
  );
}
```

点击头像，编辑器会就地展开，默认显示角色页签；上传页签会把拖入的图片放进方形裁切框。这个示例没有传 `generateImage`，所以没有生成页签。

## 三个入口

`AvatarField` 是带铅笔标记的头像，用于个人资料卡。`AvatarButton` 是普通按钮，上面用实时的 `CharacterMark` 显示当前选择，用于表单行。两者都会打开 `AvatarStudio`，并把 props 原样传给它；宿主想自己决定对话框位置时，直接使用编辑器。

铅笔使用引擎自带的 `pencilGlyphPath`，也就是 `writing` 状态下绕着角色转的那个轮廓，而不是来自某个图标库。这个库里只有一种铅笔；如果再从别处取一个，它的笔画粗细就会和旁边已经带着前一种铅笔的角色对不上。

## 怎样关闭

`onClose` 会报告 `save`、`cancel` 或 `dismiss`（按 Escape 或点击对话框外部）。`dismiss` 时，两种暂存内容的处理不同：

- 暂存的**角色**会保留。形状和墨色成本低，也可以随时改回，而且每一种组合都是合法的头像；用户点了六边形再按 Escape，就是想保留六边形。为一个只需点两下的决定再去找保存按钮，没有必要，所以 `onCommit` 会带着暂存的角色触发。
- 暂存的**图片**不会保留。裁切结果还没有人在编辑器外看过，而用一张构图糟糕的照片替换掉原来的头像，正是用户想再考虑一下的那种改动。只有点保存才会应用它。

## 页签

`characterTab={false}` 会隐藏角色页签，因为群组头像没有角色可选。只有提供了 `generateImage`，才会出现生成页签；它接收提示词和一个 `AbortSignal`，应当 resolve 为图片 URL 或 data URL。`initialTab` 指定打开时显示的页签；默认情况下，已有图片的头像会从上传页签打开。

```tsx
<AvatarButton
  value={avatar}
  onCommit={save}
  generateImage={(prompt, signal) => api.generateAvatar(prompt, { signal })}
/>
```

## 裁切辅助函数

上传页签由一组已导出的函数构成，自己实现裁切界面的宿主可以复用其中的计算和导出逻辑。

| 导出                                    | 用途                                                                                                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `readImageFile(file)`                   | 校验并读取拖放、粘贴或选择的文件。resolve 为 `{ ok, dataUrl }`，或带有 `too-large` / `not-an-image` 的 `{ ok: false, reason }`。选错文件是用户操作，不算程序错误。 |
| `loadImage(dataUrl)`                    | 解码图片，并在载入时降采样到 `MAX_SOURCE_PX`（1600），这样拖动 6000px 的照片也能保持流畅。                                                                         |
| `fitImage(width, height, max?)`         | 源图解码时应使用的尺寸。                                                                                                                                           |
| `coverScale(view)`、`clampZoom(zoom)`   | 在 `ZOOM_MIN`（1）到 `ZOOM_MAX`（4）之间的某个缩放级别下，填满裁切框所需的缩放比例。                                                                               |
| `panLimit(view)`、`clampPan(pan, view)` | 图片边缘进入裁切框之前最多能平移的距离，以及限制在该范围内的平移量。                                                                                               |
| `exportPlacement(request)`              | 源图落在导出方形上的位置。                                                                                                                                         |
| `cropToDataUrl(image, request)`         | 把裁切结果渲染为 `EXPORT_PX`（360）大小的 PNG data URL，是 `CROP_STAGE_PX`（120）裁切区域的三倍，在视网膜屏上头像依然清晰。                                        |

限制值也一并导出：`MAX_UPLOAD_BYTES`（20 MB）、`ZOOM_STEP`（0.25）。
