# 引导页组件

六个组件，用来展示智能体产品，而不必真的实现它：窗口框、进行中的任务、起点卡片、等待屏、交接和消息输入框。

> 属于 `@aora-bot/surfaces`，不在 `@aora-bot/react` 中：`pnpm add @aora-bot/surfaces @aora-bot/react`，并在 React 样式之后引入 `@aora-bot/surfaces/styles.css`。

```tsx preview
import { CharacterStageProvider } from '@aora-bot/react';
import { Composer, DemoDesktop, JobBubbles } from '@aora-bot/surfaces';

export default function Demo() {
  return (
    <CharacterStageProvider>
      <div className="site-demo site-demo--center">
        <DemoDesktop
          title="工作区"
          widthPx={380}
          toolbar={<span style={{ opacity: 0.6 }}>app.example/inbox</span>}
        >
          <div style={{ display: 'grid', gap: 16, padding: '24px 16px 12px' }}>
            <JobBubbles
              shape="blob"
              color="blue"
              radiusPx={84}
              jobs={['读需求', '起草回复', '核对数字', '开 pull request']}
            />
            <Composer placeholder="想做什么都可以说" onSubmit={() => {}} />
          </div>
        </DemoDesktop>
      </div>
    </CharacterStageProvider>
  );
}
```

## DemoDesktop

一个窗口框。引导页需要展示软件，但自己又不是那个软件，而普通卡片看不出是「应用」。窗口标题栏不用说一个字，就能让人明白「这只是另一处正在发生的事情的画面」。窗口框纯粹用于展示：它是包在宿主内容外面的 `aria-hidden` 外壳，内容保留自己的语义。`toolbar` 放在标题栏下方，用来放页签、假 URL 之类的小控件。

## JobBubbles

进行中的任务，以文字形式显示在角色周围。这里用气泡而不是列表，因为要表达的是「同时进行好几件事」，而列表看起来像队列。每个气泡以各自的周期和负的延迟漂浮，所以不会同相。一圈标签同步起伏，看起来就像一个物体在旋转。环上的气泡按真实角度排布，而不是旋转容器：容器旋转时文字也会跟着转，翻过来的标签没法读。`jobs` 默认取本地化文案中的四条，`radiusPx` 设置环的半径。

## SuggestionCards

```tsx preview
import { useState } from 'react';
import { SuggestionCards, type SuggestionCard } from '@aora-bot/surfaces';

const cards: SuggestionCard[] = [
  { id: 'triage', title: '整理收件箱', body: '把昨夜到达的邮件按该看的人分类。' },
  { id: 'standup', title: '写站会纪要', body: '从昨天的提交里提炼三行。' },
  { id: 'audit', title: '审计依赖', body: '找出过期的依赖，并说明风险有多大。' },
];

export default function Demo() {
  const [picked, setPicked] = useState<string | null>(null);
  return (
    <div className="site-demo site-demo--column">
      <SuggestionCards cards={cards} onPick={(card) => setPicked(card.title)} />
      <span className="site-demo__label">{picked ?? '选一张'}</span>
    </div>
  );
}
```

三个起点，每个都带一张脸。角色由卡片 id 推导，而不是人为指定，所以这个组件能通用：宿主传入自己的卡片，不用挑选形状，就能得到三个可以区分的智能体。推导用的是哈希而不是随机洗牌，所以同一张卡片的外观始终不变。在卡片上设置 `shape` 和 `color` 可以覆盖推导结果。

## LandingWait

```tsx preview
import { LandingWait } from '@aora-bot/surfaces';

export default function Demo() {
  return (
    <div className="site-demo">
      <LandingWait title="随时可以开始" body="给它第一个任务，它就会动起来。" />
      <LandingWait
        title="批准窗口"
        body="超时后运行会自行继续。"
        waitMs={90_000}
        action={<button className="site-btn">立即批准</button>}
      />
    </div>
  );
}
```

任何事情发生之前显示的那一屏。空白状态配上一个等待中的角色，传达的是「产品已就绪，没有出故障」，这是空屏幕自己表达不了的。不传 `waitMs` 时，底盘会累计已经等待的时间；传入后变成截止时间，角色戴上 `timer` 表盘，底盘倒计时。时钟放在底盘而不是表盘里，因为具体数字只能用文字表达：外圈只能表示时间*正在*流逝，只有文字才能说明过去了多久。`since` 让时钟从宿主已知的某个时刻开始计时。

## HandOff

```tsx preview
import { CharacterStageProvider } from '@aora-bot/react';
import { HandOff } from '@aora-bot/surfaces';

export default function Demo() {
  return (
    <CharacterStageProvider>
      <div className="site-demo site-demo--center">
        <HandOff
          from={{ id: 'ada', name: 'Ada' }}
          to={{ id: 'grace', name: 'Grace' }}
          label="发布说明"
          loop
        />
      </div>
    </CharacterStageProvider>
  );
}
```

一个智能体把工作交给另一个。`sending` 和 `receiving` 在引擎里成对设计：一个向外倾，另一个接住。所以不需要在两者之间飞一个物件，也能看懂交接，身体姿态已经表明了方向。动画分为三拍，而不是连续播放，因为这个过程有明确的开头和结尾：之前、之中、之后。`loop` 默认关闭，适合没人等它播完的营销页。

## Composer

消息输入框，旁边有一个角色关注着输入。共有三个状态，由输入框当前的操作驱动，而不是靠定时器：聚焦时是 `listening`，输入时是 `composing`，停止输入 `idleMs` 之后回到 `idle`。输入框旁边的角色只有对输入有反应才有意义，这个反应要快到看起来在关注，又要安静到不干扰书写。不传 `value` 时是非受控组件，所以放进演示时不需要额外的状态。下方的 props 表由 `ComposerProps` 生成；`sendButton` 用来隐藏发送按钮，适合自带发送控件的宿主。
