# SpriteMark

手绘角色，由与矢量角色相同的状态驱动。

```tsx preview
import { useState } from 'react';
import { SpriteMark, CharacterMark, EMOTION_IDS, getEmotion } from '@aora-bot/react';

const ids = ['02', '30', '32', '33', '34', '10', '13', '21', '00'];

export default function Demo() {
  const [id, setId] = useState('02');
  return (
    <div className="site-demo site-demo--column" style={{ alignItems: 'center' }}>
      <div className="site-demo">
        <SpriteMark src="/sprites/bao/manifest.json" emotionId={id} sizePx={120} />
        <SpriteMark src="/sprites/tapkin/manifest.json" emotionId={id} sizePx={120} />
        <CharacterMark shape="bun" color="orange" emotionId={id} sizePx={120} />
      </div>
      <div className="site-controls">
        {ids.map((i) => (
          <button key={i} className="site-btn" aria-pressed={i === id} onClick={() => setId(i)}>
            {i} {getEmotion(i)?.name.zh}
          </button>
        ))}
      </div>
    </div>
  );
}
```

两套精灵图和一个程序化角色，响应的是同一个[协议编号](/design/protocol)。如果宿主的状态逻辑是围绕 `CharacterMark` 写的，换成吉祥物时不需要改动这部分逻辑。

## 什么时候用

矢量角色是 Aora Bot 的核心：由程序生成，可随主题变化，体积极小。`SpriteMark` 用来处理矢量角色做不到的一件事：呈现一张特定的插画，例如品牌吉祥物、手绘宠物、由照片衍生的形象，这些外观无法由程序生成。

代价也是实实在在的。一套精灵图是几十个 PNG 文件，而不是几 KB 的绘制代码；它不会随主题换色；只有画过的状态才有对应的帧。请把它当作资源，而不是可配置的组件。

## 清单文件

`sprite-mate` 清单由一个存放 PNG 帧的文件夹和一个以协议编号为键的 `manifest.json` 组成：

```json
{
  "kind": "sprite-mate",
  "formatVersion": 1,
  "id": "tapkin",
  "name": { "en": "Tapkin", "zh": "塔皮" },
  "frameSize": [320, 320],
  "fps": 1,
  "anchor": [0.5, 0.94],
  "license": "MIT",
  "frames": {
    "00": ["00.png"],
    "02": ["02.png"],
    "10": ["10.png"],
    "30": ["30.png"],
    "33": ["33.png"]
  },
  "fallback": { "03": "02", "11": "30", "20": "30" }
}
```

- `frames` 把编号映射到一个或多个文件名，路径相对于清单。只有一个文件时是静帧，有多个文件时按 `fps` 播放。
- `fallback` 让精灵图把未绘制的编号指向已绘制的编号。回退链最多跟随四跳，所以写错一个编号也不会让页面卡死。
- `anchor` 是角色在帧内的站立位置，用比例表示。图片按 `object-fit: contain` 缩放，并按这个位置对齐，所以即使精灵图很高，角色的脚也仍落在容器的脚的位置上。

一个编号按以下顺序解析：编号本身，清单的 `fallback` 链，[分段回退](/design/protocol#分段)（未知的智能体工作编号显示这套精灵图的「处理中」帧，未知的情绪显示待机），最后是待机（`02`），每套合法的精灵图都必须有这一帧。

`spriteCoverage(manifest, EMOTION_IDS)` 用来检查一套精灵图：有多少编号直接对应帧，有多少通过回退对应，有多少完全没有对应，并列出所有制作问题（缺少待机帧、回退指向不存在的编号、回退成环）。建议在测试中对自己的精灵图运行一遍。

## 加载

传入 `src` 时，清单在客户端获取，并按 URL 缓存，直到页面关闭。清单到达之前以及加载失败时，组件会显示一个处于相同状态的程序化角色，所以布局不会出现空洞，状态也不会丢失。传入 `fallback="none"` 则显示空盒子。

```tsx
<SpriteMark src="/sprites/bao/manifest.json" state="thinking" />
```

服务端渲染，或清单已随应用打包时，可以直接传入清单和帧所在的目录。第一帧会作为纯标记输出。

导入的 JSON 文件会把 `kind` 推断为 `string`，因此要先用 `isSpriteManifest` 收窄类型：

```tsx
import { SpriteMark, isSpriteManifest } from '@aora-bot/react';
import manifest from './sprites/bao/manifest.json';

if (!isSpriteManifest(manifest)) throw new Error('不是 sprite-mate 清单');

<SpriteMark manifest={manifest} baseUrl="/sprites/bao/" state="thinking" />;
```

## 动效

帧用单个 `<img>` 显示，由定时器切换它的 `src`。没有 canvas，除了这次赋值，也没有逐帧执行的 JavaScript。片段的其余帧会预加载，所以切换时不会闪出空盒子。在 `prefers-reduced-motion` 下只显示第一帧。`paused` 会停在第一帧，`fps` 覆盖清单中的帧率。

## 内置图集

文档在 `/sprites/` 下提供两套演示用的精灵图，均为项目原创，采用 MIT 许可证：`bao` 有 32 个编号，每个 2 帧，由程序化的 `bao` 角色（`bun` 形状）渲染而来；`tapkin` 有 12 个编号，每个 1 帧，是一只通过提示词设计的仓鼠。两套的 `provenance` 块都记录了制作过程。
