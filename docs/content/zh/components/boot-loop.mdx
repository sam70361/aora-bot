# BootLoop

有东西正在启动，没人知道要等多久。

> 来自 `@aora-bot/surfaces`，不属于 `@aora-bot/react`：`pnpm add @aora-bot/surfaces @aora-bot/react`，并在 React 样式之后引入 `@aora-bot/surfaces/styles.css`。

```tsx preview
import { useState } from 'react';
import { BootLoop } from '@aora-bot/surfaces';

export default function Demo() {
  const [cycles, setCycles] = useState(0);
  return (
    <div className="site-demo site-demo--column">
      <BootLoop
        title="正在启动工作区"
        body={cycles >= 3 ? '比平时慢一些。' : '正在把一切接上线。'}
        durationMs={1800}
        onCycle={setCycles}
      />
      <span className="site-demo__label">已循环 {cycles} 次</span>
    </div>
  );
}
```

## 展示活动，而不是进度

无法确定时长的等待，是进度条唯一会误导用户的场合，所以这个场景改为展示活动：角色在 `working` 和 `thinking` 之间交替（腰带随之从旋涡换成三颗游走的珠子），同时一条扫描线从屏幕后方划过。`durationMs` 是每个状态停留的时间，两个状态各播放一次算一个循环。

`onCycle` 用于让宿主逐步升级提示。循环两次只是启动慢；循环十二次就是需要告知用户的问题了，而该说什么只有宿主知道。上面的示例在三个循环之后换了文案。

`inFront` 让角色显示在屏幕前面而不是后面，适合边框只是装饰、而不是启动对象本身的布局。

## LoadingCharacter

与即将出现的角色形状相同的占位符。

```tsx preview
import { useEffect, useState } from 'react';
import { LoadingCharacter } from '@aora-bot/surfaces';

export default function Demo() {
  const [ready, setReady] = useState(false);
  useEffect(() => {
    const timer = setInterval(() => setReady((r) => !r), 2200);
    return () => clearInterval(timer);
  }, []);

  return (
    <div className="site-demo">
      {(['hex', 'cloud', 'star'] as const).map((shape) => (
        <div className="site-demo__cell" key={shape}>
          <LoadingCharacter shape={shape} color="violet" ready={ready} sizePx={48} />
          <span className="site-demo__label">{ready ? '就绪' : '加载中'}</span>
        </div>
      ))}
    </div>
  );
}
```

在将要显示六边形的位置放一个灰色圆形，之后必然会发生布局偏移；在头像位置放一个转圈，则会在页面已有的动效之外再增加一种动效。这里直接使用角色轮廓（同一个形状生成器，做成 CSS mask），再叠加一层闪光。占位符和角色的轮廓完全一致，所以 `ready` 时是交叉淡入淡出，而不是直接替换。

淡入淡出期间，两层都保持挂载。如果在 `ready` 时就卸载占位符，角色的第一帧会显示在空白背景上，造成闪烁，而这正是这个组件要避免的。
