# 性能

角色是有开销的：每帧都要做一次物理积分，并写入几十个 SVG 属性。一个角色没什么影响；如果直接渲染两百个，任何机器都会掉帧。本页说明 Aora Bot 为此做了哪些优化，以及你需要做什么。

## 一个循环，而不是每个角色一个

所有角色共用同一个 `requestAnimationFrame` 循环。

```ts
import { ticker } from '@aora-bot/engine';

const stop = ticker.add((dt, now) => {
  // 每帧调用一次，在所有角色更新之后。
});
```

为每个角色各注册一个回调是最直接的做法，但很难扩展：每个回调都要维护自己的时间戳，浏览器每帧还要遍历更长的回调列表。用一个循环向订阅者分发，开销和单个角色差不多，还能保证屏幕上所有角色都按同一个时间戳计算，动画的相位不会漂移。

最后一个角色卸载时，循环完全停止。

## 让外观相同的角色共享动画

收益更大的做法是不重复运行同一个动画。`CharacterStageProvider` 为每一种不同的**外观**托管一个隐藏角色，所有可见实例都变成指向它的 `<use href>` 引用。

```tsx preview
import { CharacterStageProvider, StagedMark } from '@aora-bot/react';

const COLOURS = ['blue', 'green', 'violet', 'orange', 'magenta', 'cyan'] as const;

export default function Demo() {
  // 60 个标记，2 种外观，2 个运行中的引擎。
  return (
    <CharacterStageProvider>
      <div className="site-demo">
        {Array.from({ length: 60 }, (_, i) => (
          <StagedMark
            key={i}
            shape="blob"
            state={i % 2 ? 'thinking' : 'happy'}
            color={COLOURS[i % COLOURS.length]}
            sizePx={30}
          />
        ))}
      </div>
    </CharacterStageProvider>
  );
}
```

### 什么算同一种外观

外观由形状、状态和脸型决定，不包括墨色和尺寸。所以 60 个都处于 idle 的 blob 智能体，即使墨色各不相同，也只需要一个引擎。键由什么构成，以及为什么不该用智能体 id 作键，见 [`CharacterStageProvider`](/components/character-stage)。

### 上限

`maxSources` 限制同时运行的引擎数，默认为 36。超出后，页面会让一部分角色静止，而不是让所有角色都变慢。

```tsx
<CharacterStageProvider maxSources={16}>{children}</CharacterStageProvider>
```

## 暂停看不见的角色

`autoPause` 同时监听页面可见性、视口交叉和 `prefers-reduced-motion`，并自动调用 `pause()` / `resume()`。角色滚出屏幕再滚回来时，看起来像是一直在等待，而不是重新开始，因为 `pause()` 只冻结当前帧，不会重置姿态。

```tsx
<CharacterMark shape="blob" autoPause />
```

也可以传入选项，关闭其中某个信号，或加大交叉边距：

```tsx
<CharacterMark shape="blob" autoPause={{ rootMargin: '120px', reducedMotion: false }} />
```

宿主如果已经有自己的观察器，仍然可以用 `paused`。两者同时生效：只要有一个为真，循环就会停止。

## 退回静态图

集合非常大时，干脆不要用动画。`renderAvatarDataUrl` 生成静态 SVG，运行时没有开销：

```tsx preview
import { renderAvatarDataUrl } from '@aora-bot/react';

export default function Demo() {
  return (
    <div className="site-demo">
      {Array.from({ length: 24 }, (_, i) => (
        <img key={i} src={renderAvatarDataUrl(`user-${i}`)} width={36} height={36} alt="" />
      ))}
    </div>
  );
}
```

静态渲染也接受表情和状态，所以静止的角色仍然能表现它在做什么：

```tsx preview
import { renderStaticSvgDataUrl } from '@aora-bot/react';

const states = ['idle', 'sleeping', 'happy', 'angry', 'surprised', 'thinking'] as const;

export default function Demo() {
  return (
    <div className="site-demo">
      {states.map((state) => (
        <div className="site-demo__cell" key={state}>
          <img
            src={renderStaticSvgDataUrl({ shape: 'blob', color: 'green', state })}
            width={52}
            height={52}
            alt=""
          />
          <span className="site-demo__label">{state}</span>
        </div>
      ))}
    </div>
  );
}
```

这一点比看上去更重要。如果静态渲染器只能画中性表情，就无法展示状态列表：不管标签写的是什么，每个格子都是同一张脸。

## 减少动态效果

引擎启动前会检查 `prefers-reduced-motion`。该偏好开启后，弹簧立即收敛到目标值，只绘制一帧，不启动循环，也不发射粒子。你不需要自己处理，但可以查询这个偏好：

```ts
import { prefersReducedMotion, onReducedMotionChange } from '@aora-bot/engine';
```

## 预算

以下是在中端笔记本、60 Hz 下的大致参考：

| 并发引擎数 | 结果                                   |
| ---------- | -------------------------------------- |
| 1–12       | 开销可忽略                             |
| 12–36      | 舒适；默认上限                         |
| 36–60      | 可以运行，但留给页面其余部分的余量不多 |
| 60+        | 改用镜像、暂停或静态图                 |

真正关键的是**引擎数**，而不是角色数。镜像的开销几乎为零，所以页面可以显示几百个角色，仍然处于表格的第一行。
