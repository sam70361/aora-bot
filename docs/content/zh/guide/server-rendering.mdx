# 服务端渲染

哪些内容不需要 DOM 就能渲染，以及角色怎样在任何 JavaScript 运行之前就出现在 HTML 里。

## 两个入口

| 导入                     | 包含            | 没有 DOM 也安全 |
| ------------------------ | --------------- | --------------- |
| `@aora-bot/react`        | 全部组件与 Hook | 否              |
| `@aora-bot/react/static` | 渲染函数与哈希  | 是              |

静态入口有意不包含动画运行时。它导出的内容都不会访问 `window`、`document` 或 `requestAnimationFrame`，因此可以在 React Server Component、静态生成或 worker 里使用。

```ts
import { renderAvatarDataUrl } from '@aora-bot/react/static';

export default async function Page() {
  return <img src={renderAvatarDataUrl('ada@example.com')} width={40} height={40} alt="" />;
}
```

## Next.js App Router

组件包带有 `'use client'` 标记，所以可以放心地在服务端组件里导入，客户端边界已经声明好了。

```tsx
// app/page.tsx — 服务端组件
import { CharacterMark } from '@aora-bot/react';

export default function Page() {
  return <CharacterMark shape="blob" color="blue" />;
}
```

在根 layout 里引入一次样式表：

```tsx
// app/layout.tsx
import '@aora-bot/react/styles.css';
```

### 能用静态入口就用静态入口

长列表、邮件或元数据里的角色不需要动画。使用静态入口，可以让动画运行时完全不进入客户端包。

## 服务端渲染产出什么

组件在服务端渲染的是没有动画的标记。角色以静止姿态出现，水合后由引擎接管。因此不会产生布局偏移：服务端 SVG 占据的盒子，和动画角色之后占据的盒子完全一致。

```tsx preview
import { renderStaticSvg } from '@aora-bot/react';

export default function Demo() {
  const svg = renderStaticSvg({ shape: 'hex', color: 'green', expression: 'happy' });
  return (
    <div className="site-demo site-demo--column">
      <div dangerouslySetInnerHTML={{ __html: svg }} style={{ width: 90 }} />
      <pre style={{ maxHeight: 180, overflow: 'auto', fontSize: 12 }}>
        <code>{svg.slice(0, 400)}…</code>
      </pre>
    </div>
  );
}
```

## 深色与浅色模式下的墨色

对 CSS 来说，静态 SVG 是一份独立的文档，读不到应用的主题 class。所以 `renderStaticSvg` 会把调色板墨色的浅色值和深色值都写进去，再由 `colorScheme` 决定用什么机制来切换：

| `colorScheme`      | 机制                                           | 用在哪里                                                |
| ------------------ | ---------------------------------------------- | ------------------------------------------------------- |
| `'system'`（默认） | SVG 内部的 `prefers-color-scheme` 媒体查询     | `<img src="data:…">`、文件、邮件：图像与页面隔离        |
| `'page'`           | `light-dark()`，由继承来的 `color-scheme` 解析 | 内联进有自己主题开关的页面（`dangerouslySetInnerHTML`） |

`system` 跟随操作系统，因为隔离的图像只能看到系统设置。如果把它内联进读者可以切换主题的页面，它会跟着系统而不是页面：系统是深色、站点是浅色时，黑色的墨色会在浅色卡片上变成近白色。`page` 则和页面其余的 UI 一样跟随 `color-scheme`。默认输出不变。两种模式使用不同的类名，可以出现在同一个文档里。类名还包含外观信息（画风、变体和参数），所以同一个角色的两种外观内联在同一页面时，不会互相覆盖颜色规则。

相同的参数生成相同的标记，包括 id。SVG 里按 id 引用的图案、渐变和遮罩，在定义它们的位置绘制，所以同一个 `page` 角色内联两次（一次在 `color-scheme: light` 下，一次在 `dark` 下）时，纹理会按排在前面的那一份的明暗来绘制。要并排预览浅色和深色，请用 `<img>` 数据 URL，或放进两个文档。

```tsx
renderStaticSvg({ shape: 'hex', color: 'black', colorScheme: 'page' });
```

## Data URL

`renderStaticSvgDataUrl` 使用百分号编码，而不是 base64。输出更小，在开发者工具里也仍然可读。它还替你处理了一个细节：SVG data URL 里没有转义的 `#` 会把 URL 在片段处截断，这是内联 SVG 悄悄失效的常见原因。
