# 智能体集成

用一张脸展示 AI 智能体正在做什么。

整体由四部分组成：任何脚本都能发出的[数字协议](/design/protocol)；把多个来源的嘈杂状态合成为一个平稳状态的**仲裁器**；经 HTTP、stdin、`postMessage` 或服务端事件传递消息的**通道**；以及把结果接到角色上的 React Hook。

```tsx preview
import { AgentStateProvider, useAgentState, CharacterMark, ActivityLine } from '@aora-bot/react';

function Face() {
  const { state, tips, update, remove } = useAgentState();
  const report = (sessionId: string, emotionId: string, tips?: string) =>
    update({ sessionId, emotionId, tips });
  return (
    <div className="site-demo site-demo--column" style={{ alignItems: 'center' }}>
      <CharacterMark shape="blob" color="blue" state={state} sizePx={120} />
      <ActivityLine text={tips ?? state} />
      <div className="site-controls">
        <button className="site-btn" onClick={() => report('a', '30', '正在思考')}>
          a: 30 思考
        </button>
        <button className="site-btn" onClick={() => report('a', '40', '正在检索代码库')}>
          a: 40 检索
        </button>
        <button className="site-btn" onClick={() => report('b', '34', '测试失败')}>
          b: 34 出错
        </button>
        <button className="site-btn" onClick={() => report('a', '33', '完成')}>
          a: 33 完成
        </button>
        <button className="site-btn" onClick={() => (remove('a'), remove('b'))}>
          结束会话
        </button>
      </div>
    </div>
  );
}

export default function Demo() {
  return (
    <AgentStateProvider>
      <Face />
    </AgentStateProvider>
  );
}
```

在 _a_ 检索时按下 _b: 34 出错_，出错的状态胜出。紧接着 _a: 30_ 按下 _a: 33 完成_，完成会排在停留时间之后，但仍然会播放，因为它是事件。结束两个会话后，脸回到待机。

## 线上格式

所有传输方式使用同一种消息格式：

```json
{ "session_id": "s1", "aoraBotId": "32", "tips": "Editing src/app.ts" }
{ "session_id": "s1", "agent_id": "claude-code", "event": "PreToolUse" }
{ "session_id": "s1", "state": "thinking" }
{ "session_id": "s1", "aoraBotId": "47", "tips": "Indexing 3 of 8", "hud": { "kind": "progress", "value": 0.375 } }
```

- `session_id` 必填。同一 id 的后续消息更新同一个会话。
- 此外还需要**三选一**：协议编号（`aoraBotId` 或 `emotionId`）、状态名（`state`），或 `agent_id` 加上工具自己的 `event` 名，后者由[适配器](#适配器)翻译。
- `tips` 是可选的说明文字，宿主可以显示在角色旁边。
- `hud` 是可选的表盘，即画在身体外圈环上的 [`HudSpec`](/design/protocol#hud)，用 `isHudSpec` 校验。格式不合法的会被丢弃，消息本身照常生效。
- `headless: true` 标记只记录、从不显示的会话，用于不该占用脸的后台任务。

`normalize(message)` 把上述任一形式转换成仲裁器更新，或返回一条错误字符串，不会抛出异常。

```ts
import { normalize } from '@aora-bot/engine/agent';

normalize({ session_id: 's1', aoraBotId: '32' });
// { ok: true, update: { sessionId: 's1', emotionId: '32', state: 'working', headless: false } }

normalize({ session_id: 's1', agent_id: 'claude-code', event: 'Stop' });
// { ok: true, update: { …, emotionId: '33', state: 'celebrate' } }

normalize({ aoraBotId: '32' });
// { ok: false, error: 'missing session_id' }
```

`@aora-bot/engine/agent` 是独立的入口，不含 DOM 和动画代码，因此在 Node 中继里和在浏览器里都能加载。

## 仲裁

一个角色可能对应多个来源：比如带三个子智能体的编码智能体，或者一个聊天窗口加一个后台构建。每个来源各自报告状态，由仲裁器决定角色显示什么。规则有四条：

1. **优先级。** 在可见会话中，优先级最高的状态胜出。三个会话在工作、一个在报错时，显示报错。出错和拒绝的优先级最高，因为需要人来处理；完成高于进行中的工作，因为它是结果；工作高于待机。
2. **最短停留。** 一个状态显示满 `minDisplayMs`（默认 900 ms）后才能被替换。没有这条规则，连续的工具事件会让脸不停闪烁；有了它，每个表情都能稳定显示，让人看清。
3. **事件与条件。** 一次性编号（完成、出错、惊讶）是事件，从不丢弃：在停留期间到达的会排队，停留结束后播放。持续状态是条件：停留结束时仲裁器会重新解析，因为情况可能已经变了。
4. **过期。** 超过 `sessionTtlMs`（两分钟）没有消息的会话会被清除，这样没有会话结束钩子的工具也不会让角色永远停在某个状态。

```ts
import { createArbiter } from '@aora-bot/engine/agent';

const arbiter = createArbiter({
  minDisplayMs: { defaultMs: 900, byState: { celebrate: 2000, alerting: 1500 } },
  priority: { searching: 45 }, // 覆盖某一个状态
  onApply: ({ state, tips }) => character.update({ state }),
});

arbiter.update({ sessionId: 'a', emotionId: '30' });
arbiter.update({ sessionId: 'b', emotionId: '34', tips: 'Build failed' });
arbiter.resolve(); // { state: 'alerting', emotionId: '34', tips: 'Build failed', sessionId: 'b' }：按优先级胜出的会话
arbiter.current(); // { state: 'thinking', … }：屏幕上正在显示的；`thinking` 的 900 ms 停留还没结束

arbiter.update({
  sessionId: 'b',
  emotionId: '47',
  tips: 'Rebuilding',
  hud: { kind: 'progress', value: 0.2 },
});
arbiter.resolve().hud; // { kind: 'progress', value: 0.2 }：胜者的表盘，与它的 tips 并排
```

`resolve()` 不考虑停留，直接返回按优先级胜出的会话；`current()` 返回角色当前显示的内容，停留结束后会更新到最新结果（通过 `onApply` 通知）。

`tips` 和 `hud` 属于会话本身，随会话一起传递：结果里只有胜出会话的说明和表盘，落败会话的都不会带上。因此后台任务不能把自己的进度环画到前台智能体的脸上。

时钟和定时器可以注入，因此整套逻辑在测试中可以确定地重复运行。

在 React 里，[`useArbiter`](/components/agent-state) 在组件的整个生命周期内运行一个仲裁器，`AgentStateProvider` 把它共享给整棵子树。`hud` 与 `tips` 一样出现在 provider 的值上，[`AgentHud`](/components/agent-hud) 无需额外配置，就能从 provider 渲染角色、表盘和说明。

## 适配器

适配器把某个工具的事件名映射到协议编号上。它是纯数据：要支持另一个智能体，只需新增一个对象，不用写新的逻辑。

```tsx preview
import { AGENT_ADAPTERS, stateForEmotion } from '@aora-bot/react';

export default function Demo() {
  return (
    <div className="site-demo" style={{ alignItems: 'flex-start' }}>
      {AGENT_ADAPTERS.map((adapter) => (
        <table key={adapter.id} style={{ margin: 0 }}>
          <thead>
            <tr>
              <th colSpan={3}>
                {adapter.name} <code>{adapter.id}</code>
              </th>
            </tr>
          </thead>
          <tbody>
            {Object.entries(adapter.events).map(([event, id]) => (
              <tr key={event}>
                <td>
                  <code>{event}</code>
                </td>
                <td>
                  <code>{id}</code>
                </td>
                <td>{stateForEmotion(id)}</td>
              </tr>
            ))}
          </tbody>
        </table>
      ))}
    </div>
  );
}
```

如果宿主知道的是正在运行哪个*工具*，而不是触发了哪个生命周期事件，可以用 `stateForTool('grep')`。它查的是另一张表 `TOOL_STATES`，[`ActivityBadge`](/components/activity-badge) 用的也是这张表。

### 活动动词与名册事实

第三张表回答第三个问题。`TOOL_STATES` 回答「哪个工具在运行」；`ACTIVITY_VERBS` 回答「该告诉用户它在做什么」，也就是角色旁边已经显示的那句话。`stateForActivity('coding')` 把动词解析为状态，不认识的动词一律按通用的工作状态处理，所以宿主只有「Running commands…」这样一句话时，也能驱动角色。查表时使用 `Object.hasOwn`：动词来自传输的消息，不能让 `"constructor"` 之类的名字命中原型链上的属性。

```tsx preview
import { ACTIVITY_VERB_IDS, CharacterStageProvider, StagedMark, stateForActivity } from '@aora-bot/react';

export default function Demo() {
  return (
    <CharacterStageProvider>
      <div className="site-demo">
        {ACTIVITY_VERB_IDS.map((verb) => (
          <div className="site-demo__cell" key={verb}>
            <StagedMark shape="pebble" color="blue" state={stateForActivity(verb)} sizePx={40} />
            <span className="site-demo__label">{verb}</span>
          </div>
        ))}
      </div>
    </CharacterStageProvider>
  );
}
```

名册中的一行通常比一个动词包含更多信息：智能体是否 `running`、是否正在 `composing` 回复，以及它报告的 `activity`。`characterStateForRoster(facts, surface)` 把这些 `RosterFacts` 解析为状态，结果取决于角色画在哪个位置。在 `chat` 行里，撰写状态正是重点，因为回复正在用户眼前生成。在 `avatar` 场景下，撰写状态每几百毫秒就切换一次，二十张脸在两个状态间来回闪动只是干扰，所以头像保持待机，直到有值得展示的内容。`activityMode="facts"` 的 `ActivityBadge` 和[角色指令](/components/mark-commands)注册表都通过这个函数解析，因此同一个智能体在各处显示的状态一致。

```ts
characterStateForRoster({ running: true, composing: true }, 'chat'); // 'composing'
characterStateForRoster({ running: true, composing: true }, 'avatar'); // 'working'
characterStateForRoster({ running: true, activity: 'searching' }, 'list'); // 'searching'
characterStateForRoster({}, 'list'); // 'idle'
```

## 配方

### 一个中继

智能体在终端里运行，角色在页面里运行，两者之间需要有程序传递消息。仓库的 `examples/agent-relay` 里提供了一个：零依赖的 Node 脚本，接受 `POST /state` 和 stdin 上按行分隔的 JSON，对两者做归一化后，通过服务端事件广播给浏览器。

```bash
node examples/agent-relay/relay.mjs            # http://127.0.0.1:27182
my-agent --emit-json | node examples/agent-relay/relay.mjs --stdin
```

它只由 `normalize`、`readLineStream` 和一个存放响应流的 `Set` 组成。建议改写成自己的版本，不要直接依赖它。

消息可以带 `hud` 字段。中继会像校验其余内容一样校验它，无效的 `hud` 会被丢弃，消息照常生效。`hud` 随胜出会话的状态一起传播，所以 `/events` 和中继的 `/preview.svg` 都会显示它：

```bash
curl -X POST http://127.0.0.1:27182/state \
  -H 'content-type: application/json' \
  -d '{"session_id":"s1","aoraBotId":"47","tips":"Indexing 3 of 8","hud":{"kind":"progress","value":0.375}}'
```

```tsx
import {
  AgentStateProvider,
  useEventSourceChannel,
  useAgentState,
  CharacterMark,
  AgentHud,
} from '@aora-bot/react';

function Pet() {
  const status = useEventSourceChannel('http://127.0.0.1:27182/events');
  const { state, hud } = useAgentState();
  return (
    <span data-connection={status}>
      <CharacterMark state={state} hud={hud ?? null} />
    </span>
  );
}

// 或者，让角色、表盘和说明一起出现：
function Panel() {
  useEventSourceChannel('http://127.0.0.1:27182/events');
  return <AgentHud agent={{ id: 'relay' }} />;
}

<AgentStateProvider>
  <Pet />
</AgentStateProvider>;
```

### Claude Code 钩子

Claude Code 会在生命周期事件上触发 shell 钩子。每个钩子带着适配器 id 和事件名，向中继发送 POST 请求，翻译由适配器完成。把它们写进 `~/.claude/settings.json`：

```json
{
  "hooks": {
    "UserPromptSubmit": [{ "hooks": [{ "type": "command", "command": "aora-report UserPromptSubmit" }] }],
    "PreToolUse": [{ "hooks": [{ "type": "command", "command": "aora-report PreToolUse" }] }],
    "PostToolUse": [{ "hooks": [{ "type": "command", "command": "aora-report PostToolUse" }] }],
    "PostToolUseFailure": [{ "hooks": [{ "type": "command", "command": "aora-report PostToolUseFailure" }] }],
    "Notification": [{ "hooks": [{ "type": "command", "command": "aora-report Notification" }] }],
    "Stop": [{ "hooks": [{ "type": "command", "command": "aora-report Stop" }] }],
    "SessionEnd": [{ "hooks": [{ "type": "command", "command": "aora-report SessionEnd" }] }]
  }
}
```

```bash
#!/bin/sh
# aora-report —— 钩子从 stdin 收到 JSON；session_id 就在里面。
SESSION=$(jq -r .session_id)
curl -s -o /dev/null -X POST http://127.0.0.1:27182/state \
  -H 'Content-Type: application/json' \
  -d "{\"session_id\":\"$SESSION\",\"agent_id\":\"claude-code\",\"event\":\"$1\"}"
```

子智能体用各自的 `session_id` 报告，所以父智能体在等待、三个子智能体在工作时，共有三个工作中的会话，脸显示为工作状态。

### Cursor 钩子

格式相同，用 `agent_id: "cursor"` 加上 Cursor 的事件名：`toolCall`、`fileEdit`、`shellCommand`、`webSearch`、`awaitingApproval`、`responding`、`taskComplete`、`error`。适配器没有列出的事件，可以直接发送编号：

```bash
curl -X POST http://127.0.0.1:27182/state -H 'Content-Type: application/json' \
  -d '{"session_id":"cursor-1","aoraBotId":"39","tips":"正在撰写回答"}'
```

### iframe 或扩展面板

智能体在另一个文档里时，向 frame 发送消息：

```ts
// 宿主文档
frame.contentWindow.postMessage(
  { type: 'aora:state', payload: { session_id: 'host', state: 'thinking' } },
  'https://widget.example',
);
```

```tsx
// frame 内部
function Widget() {
  useStateChannel({ allowOrigin: 'https://app.example' });
  const { state } = useAgentState();
  return <CharacterMark state={state} />;
}
```

`useStateChannel` 只接受来自允许的来源（默认是页面自身的来源）、类型为 `aora:state` 的消息，并把它们交给最近的 `AgentStateProvider`。

## 访客走神时一起打盹

侧边栏里的角色不该一直睁着眼睛看一个小时。`useIdleSleep` 监听文档上的输入，先返回 `drowsy`，再返回 `sleeping`，输入恢复时短暂返回 `waking`。访客活跃时它返回 `null`，因此可以写成回退的形式，与智能体状态组合：

```tsx
const idle = useIdleSleep({ drowsyAfterMs: 45_000, sleepAfterMs: 120_000 });
const { state } = useAgentState();
<CharacterMark state={idle.state ?? state} />;
```

见 [`useIdleSleep`](/components/use-idle-sleep)。
