# 无障碍

角色旁边该写什么，以及为什么不能只靠角色传达信息。

## 角色默认是装饰

每个角色都带 `aria-hidden="true"`。这是合理的默认值：名字旁边的角色只是视觉点缀，如果对话的每一行前都读出「图片」，屏幕阅读器就没法用了。

这也意味着**角色本身从不单独传达信息**。这条约束同样适用于你的代码，不只是 Aora Bot 自己。

## 含义必须落在哪里

44 种动画状态传递着实际信息：正在工作、在等你、被卡住、已经完成。看不到动画的读者拿不到这些信息，所以要把同样的事实写成文字：

```tsx
// 不要这样：状态是唯一信号。
<CharacterMark state={agent.running ? 'working' : 'idle'} />

// 这样：角色装饰一个已经可读的事实。
<span>
  <CharacterMark state={agent.running ? 'working' : 'idle'} />
  <span>{agent.running ? '正在跑测试' : '空闲'}</span>
</span>
```

`ActivityBadge` 已经替你做了这件事：角色和文字标签出自同一个数据源，两者不会互相矛盾。

## 当角色是唯一内容

单独出现、旁边没有名字的头像本身就是内容，需要一个可访问名称：

```tsx
<span role="img" aria-label={`${user.name} 的头像`}>
  <AgentPortrait agent={user} />
</span>
```

不要把形状或墨色写进标签。「蓝色云朵」描述的是画面，读者需要知道的是这个人。

## 动效

引擎启动前会读取 `prefers-reduced-motion`。该偏好开启时：

- 弹簧立刻落到目标值
- 只绘制一帧，不启动动画循环
- 不发射粒子
- 组件层的 CSS 过渡被关闭

这不是多余的谨慎。有些状态会引发前庭不适：`celebrate` 让角色原地转身并甩出一圈彩带，`burst()` 从中心向外抛出粒子。这两种效果都会被抑制。

如果你自己驱动动效，也要检查同一个偏好：

```ts
import { prefersReducedMotion, onReducedMotionChange } from '@aora-bot/engine';

if (!prefersReducedMotion()) confetti.current?.burst();
```

不要在读者没有主动操作时调用 `spin()` 或 `burst()`。

## 可交互的角色

要把角色当按钮用，就使用真正的按钮元素。

```tsx
<button type="button" aria-label="更换头像" onClick={open}>
  <AgentPortrait agent={user} />
</button>
```

`CharacterSelector` 由两组单选项构成：每个选项都有 `role="radio"`、可访问名称和可见的焦点环，方向键和 `Tab` 的行为符合预期。

## 颜色

组件层从不把颜色当作唯一信号。`AvatarStatusDot` 接受可选的 `label`；`UnreadBadge` 的可见文本最多显示到 `99+`，但会向辅助技术完整播报实际数量。

墨色之间并不保证色觉障碍的读者都能分辨，所以不要只靠角色的墨色表示状态。

## 清单

- 除非给角色一个名称，否则它是 `aria-hidden` 的
- 每种动画状态附近都有等价的文字
- 在 `prefers-reduced-motion` 下抑制动效
- 可交互的角色是带标签的真按钮
- 没有任何含义只靠颜色传达
