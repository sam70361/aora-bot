# 拒绝与限制

拒绝用户的页面，以及怎样拒绝才不会像出了故障。

## 先看效果

三种 `tone`，以及各自对应的名册状态点。切换 `tone` 会更换文案和边框指示灯；`action` 插槽放的是用户的出路，具体是什么由宿主决定。

```tsx preview
import { useState } from 'react';
import { AgentPortrait, AvatarStatusDot, CharacterStageProvider } from '@aora-bot/react';
import { RestrictedScene, type RestrictedTone } from '@aora-bot/surfaces';

const tones: RestrictedTone[] = ['restricted', 'unauthorised', 'offline'];
const dot: Record<RestrictedTone, { tone: 'error' | 'offline'; label: string }> = {
  restricted: { tone: 'error', label: '受限' },
  unauthorised: { tone: 'error', label: '需要登录' },
  offline: { tone: 'offline', label: '离线' },
};

export default function Demo() {
  const [tone, setTone] = useState<RestrictedTone>('restricted');

  return (
    <CharacterStageProvider>
      <div className="site-demo site-demo--stack">
        <RestrictedScene
          tone={tone}
          state={tone === 'offline' ? 'sleeping' : 'refusing'}
          color="orange"
          rotateMs={0}
          action={
            <button
              className="site-btn"
              onClick={() => setTone(tones[(tones.indexOf(tone) + 1) % tones.length]!)}
            >
              下一个 tone
            </button>
          }
        />
        <div className="site-demo__row">
          <span className="site-demo__avatar">
            <AgentPortrait
              agent={{ id: 'ledger', name: 'Ledger' }}
              state={tone === 'offline' ? 'sleeping' : 'idle'}
              sizePx={40}
            />
            <span className="site-demo__dot">
              <AvatarStatusDot tone={dot[tone].tone} label={dot[tone].label} />
            </span>
          </span>
          <span className="site-demo__label">Ledger, {dot[tone].label}</span>
        </div>
      </div>
    </CharacterStageProvider>
  );
}
```

`rotateMs={0}` 会固定使用第一个形状；默认每十二秒换一次，启用减少动态效果时停止，因为轮廓变形也属于动态，即使屏幕上没有东西在移动。名册状态点对策略性拒绝用 `error`，对已宕机的服务用 `offline`，和场景用边框指示灯表示的区别一致。

## 什么时候用

用户被拒绝时看到的那一页：套餐限额、地区封锁、登录过期、服务宕机。这也是放角色代价最小的一屏，原因见 [`RestrictedScene`](/components/restricted-scene)。

## 用到的组件

- [`RestrictedScene`](/components/restricted-scene)——完整的拒绝页：边框、角色、标题、正文、出路。`tone` 决定文案和边框指示灯。
- `DeviceBezel`——只要边框，适合自行排版的场景。
- [`CharacterMark`](/components/character-mark)——`refusing` 表示拒绝，`alerting` 表示出了问题。
- [`AvatarStatusDot`](/components/avatar-frame)——`error` 和 `offline` 两种 tone，在名册角落表达同样的信息。
- [`HudPlate`](/components/hud-plate)——限制会自行解除时（限流、冷却）用 `timer` 表盘，逐渐消退的环告诉用户稍等，而不是离开；服务宕机时用 `sync` 的 `error`，表示生命周期失败，而不必编造数字。

## 状态怎么走

| 从         | 到         | 时机                                          |
| ---------- | ---------- | --------------------------------------------- |
| 任意       | `alerting` | 请求失败；`bang` 腰带弹入，协议编号 `47`      |
| `alerting` | `refusing` | 失败是策略而不是意外——编号 `49`               |
| `alerting` | `idle`     | 故障是暂时的，重试成功了                      |
| `refusing` | `idle`     | 用户获得权限、升级套餐或完成登录              |
| 任意       | `sleeping` | 服务下线；`tone="offline"` 会把边框指示灯关掉 |

`alerting` 有意做得很醒目，但持续时间应当很短。`refusing` 会被人盯着看很久，所以它很安静：皱眉、眯眼、没有腰带，场景每十二秒换一次轮廓，长时间盯着看也不会像卡住了。

## 每个状态的样子

<StateMatrix states={['alerting', 'refusing', 'sleeping', 'idle']} />

`bang` 进场时过冲一次，之后以两秒为周期缓慢脉动，而不是闪烁：一眼看去，这就是「请看这里」与错误指示灯的区别。`refusing` 在线条脸模式下仍保留皱眉，而多数负面状态在线条脸里会松成一条平线，因为不皱眉的拒绝看上去像是无所谓。
