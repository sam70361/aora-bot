# 智能体名册

工作区侧边的二十个智能体，每个都有自己的脸。

## 先看效果

三行智能体加一个群组。每行从注册表读取状态，状态点和徽标由宿主自己的数据决定；按钮模拟真实宿主会发布的事件。

```tsx preview
import { useState } from 'react';
import {
  AgentPortrait,
  AvatarGroup,
  AvatarStatusDot,
  CharacterStageProvider,
  UnreadBadge,
  WorkingBadge,
  useMarkCommand,
  useMarkCommands,
} from '@aora-bot/react';

const agents = [
  { id: 'nova', name: 'Nova' },
  { id: 'atlas', name: 'Atlas' },
  { id: 'iris', name: 'Iris' },
];

function Row({ agent }: { agent: (typeof agents)[number] }) {
  const commands = useMarkCommands();
  const snapshot = useMarkCommand(agent.id, 'avatar');
  const [unread, setUnread] = useState(0);
  const running = snapshot.facts?.running === true;

  return (
    <div className="site-demo__row">
      <span className="site-demo__avatar">
        <AgentPortrait agent={agent} state={snapshot.state} sizePx={40} />
        <span className="site-demo__dot">
          <AvatarStatusDot tone={running ? 'working' : 'online'} label={running ? '工作中' : '在线'} />
        </span>
        <span className="site-demo__count">
          <UnreadBadge count={unread} />
        </span>
      </span>
      <span className="site-demo__who">{agent.name}</span>
      {running && <WorkingBadge />}
      <span className="site-controls">
        <button
          className="site-btn"
          onClick={() =>
            running
              ? commands.releaseFacts(agent.id)
              : commands.holdFacts(agent.id, { running: true, activity: 'coding' })
          }
        >
          {running ? '停止' : '开始'}
        </button>
        <button
          className="site-btn"
          onClick={() => {
            setUnread((n) => n + 1);
            commands.holdState(agent.id, 'notifying', { ttlMs: 1400 });
          }}
        >
          来消息
        </button>
        <button
          className="site-btn"
          onClick={() => {
            commands.releaseFacts(agent.id);
            commands.holdState(agent.id, 'celebrate', { ttlMs: 1600 });
          }}
        >
          完成
        </button>
      </span>
    </div>
  );
}

export default function Demo() {
  return (
    <CharacterStageProvider>
      <div className="site-demo site-demo--column">
        {agents.map((agent) => (
          <Row key={agent.id} agent={agent} />
        ))}
        <div className="site-demo__row">
          <AvatarGroup members={[...agents, { id: 'echo' }, { id: 'sol' }]} sizePx={40} />
          <span>全体</span>
        </div>
      </div>
    </CharacterStageProvider>
  );
}
```

`holdState` 优先于事实，所以庆祝会盖在这一行已有的任何状态之上，存活时间一到就交还。`WorkingBadge` 有意与角色分开：一行可以在忙，脸却不必表现出来，长列表因此能保持安静。

## 什么时候用

工作区侧边的智能体列表：有哪些智能体、谁在忙、谁有消息要给你。这里的角色首先代表身份，其次才是状态：脸由智能体 id 推导而来，固定不变，不用另外存储。屏幕上同时有二十行，任何会动的东西都要值得它占用的注意力，所有行也共用一个舞台。

## 用到的组件

- [`AgentPortrait`](/components/agent-portrait)——根据智能体记录，自动选择显示照片、群组头像还是角色。
- [`AvatarGroup`](/components/avatar-group)——群组成员头像；每个头像按自己的轮廓，从后一个头像上镂空出来。
- [`AvatarStatusDot`](/components/avatar-frame) 与 [`UnreadBadge`](/components/avatar-frame)——头像角落的在线状态和未读计数。
- [`WorkingBadge`](/components/working-badge)——三个错开节奏的点，用于在忙但脸不必动的行。
- [`useMarkCommands`](/components/mark-commands)——提供 `holdFacts`、`holdState`、`releaseState`；名册和对话读取同一份注册表。
- [`CharacterStageProvider`](/components/character-stage)——二十个空闲角色只占用一个引擎。

## 状态怎么走

| 从        | 到          | 时机                                          |
| --------- | ----------- | --------------------------------------------- |
| —         | `idle`      | 还没有这个智能体的任何信息                    |
| `idle`    | `working`   | `holdFacts` 传入 `running: true`              |
| `working` | `idle`      | 事实被释放                                    |
| `idle`    | `notifying` | 有消息到达——`holdState` 带 `ttlMs`，编号 `50` |
| 任意状态  | `waiting`   | 智能体在等用户——`characterStateForAgent`      |
| 任意状态  | `celebrate` | 任务完成——`holdState` 带 `ttlMs`，编号 `33`   |
| 任意状态  | `sleeping`  | 智能体离线；搭配 `offline` 状态点             |

用 `useMarkCommand(id, 'avatar')` 读取注册表。要注意读取的界面：`composing` 事实在头像上会解析为 `idle`，因为正在撰写的回复在对话里是重点，在二十张脸的列表里则是干扰。

## 每个状态的样子

<StateMatrix states={['idle', 'working', 'waiting', 'notifying', 'celebrate', 'sleeping']} />

`waiting` 把身体的动作让给 `orbit` 腰带；`notifying` 身体照常，改为点亮角落的徽标。`idle` 的眨眼和张望由三条频率互不相关的正弦波驱动，所以一行放上十分钟也看不出重复。
