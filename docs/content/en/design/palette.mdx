# Palette

Every hue carries three layers: a chip value for pickers, a body ink per colour scheme, and a gradient pair for static avatars.

<PaletteGrid />

## Three layers per hue

A picker chip and a rendered character have opposite problems. The chip is a 20-pixel square that has to be told apart from its neighbours. The character is a large filled silhouette that has to stay readable on both a white and a near-black page. One value cannot do both jobs: tuned for the chip it makes the bodies glaring, tuned for the body it makes the chips muddy.

So each hue carries three layers.

| Layer      | Purpose                                               |
| ---------- | ----------------------------------------------------- |
| `value`    | Flat chip colour, tuned for recognition at small size |
| `ink`      | Two values, one per scheme, for the character body    |
| `gradient` | Two pairs, for static avatars                         |

```tsx preview
import { COLOR_SWATCHES, getSwatchHex, getInkColor } from '@aora-bot/react';

export default function Demo() {
  return (
    <div className="site-demo">
      {COLOR_SWATCHES.map((s) => (
        <div className="site-demo__cell" key={s.id} style={{ minWidth: 92 }}>
          <div style={{ display: 'flex', gap: 2 }}>
            <span style={{ width: 26, height: 26, borderRadius: 6, background: getSwatchHex(s.id) }} />
            <span
              style={{ width: 26, height: 26, borderRadius: 6, background: getInkColor(s.id, 'light') }}
            />
            <span style={{ width: 26, height: 26, borderRadius: 6, background: getInkColor(s.id, 'dark') }} />
          </div>
          <span className="site-demo__label">{s.id}</span>
        </div>
      ))}
    </div>
  );
}
```

## Automatic light and dark

Ink is emitted as a `light-dark()` pair and written into a CSS custom property once:

```ts
getInkColorCss('blue'); // → light-dark(#2B8FFF, #2884EB)
```

The browser re-resolves it when `color-scheme` changes. That is the whole theme-switching mechanism — no listener, no re-render, no flash, and it costs the same for one character as for a thousand.

## black inverts

`black` is the only hue whose dark-mode ink is not a darker version of its light-mode ink — it becomes white. The neutral character is meant to be the one with the most contrast against the page, and on a dark page that means going the other way.

## Cream and the muted colours

`cream` is a warm off-white. It leads `COLOR_IDS` and is Dot's colour; being so light, it wears the dark face, as `yellow` does. `ivory`, the white of the palette, follows it. Both all but match a light page, so a filled body in either takes a hairline edge in its line ink there (`--aora-rim`), one screen pixel wide at any size, in every filled variant and medium; on a dark page they read without one, and `night` takes the same edge on a dark page. `sage`, `clay`, `navy` and `mauve` are four muted colours after the bright hues; `navy` is lifted a step on a dark page so that it does not sink into it. `night` is a near-black that stays dark on a dark page; it is accepted by id but left out of the default lists (`UNLISTED_COLOR_IDS`).

## The face rule

Every paint of the face is measured against the body it is drawn on, by WCAG contrast, and on each page on its own, since the ink differs between them. No colour is listed by name: each paint has a colour it prefers and takes the other one only where that reads better.

| Paint                                                                                                                                   | Prefers              | Least contrast it keeps |
| --------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ----------------------- |
| The `cute` face, a drawn face's whites, the sticker's face                                                                              | White                | 2.4                     |
| The features: the `eyes` and `line` faces; brows, lids and eyes drawn straight on a body; the face of `soft`, `crayon` and `watercolor` | Dark brown `#2B2420` | 3                       |
| The shade laid over hair                                                                                                                | Black                | 1.8                     |

So a hue in the middle of the range keeps the white face and the dark features. A light ink (`cream`, `ivory`, `yellow`, `butter`, `sky`) takes the dark face with light pupils. A dark one (`navy`, `cocoa`) keeps the white face and turns its features white too, and a nearly black one (`night`) its hair shading as well. A pupil is whatever reads on the face, and the light on a body-drawn eye whatever reads on the features.

Every face takes its paints from these roles, so faces differ only in how many they use: the `cute` face uses the face colour, the `eyes` and `line` faces the features colour, and a drawn face both, with pupils and lights. The colour depends on the body alone, never on the page behind it, so a body that keeps its ink on both pages keeps its face too; `black`, which turns white on a dark page, turns its face with it.

## Variables beyond the ink

The body ink is `--aora-fg`, but the face and a couple of variants need colours of their own. When you style a character yourself, write them all with `getInkVars(color)` rather than `--aora-fg` alone; `CharacterMark` and `StagedMark` do exactly that. On a hue in the middle of the range only `--aora-face` is written, white, and the tokens' defaults do the rest.

| Variable              | Used for                                                                                            | Value                                                                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `--aora-fg`           | The body ink                                                                                        | The hue's `light-dark()` pair                                                                                                              |
| `--aora-face`         | The colour of the `cute` face and a drawn face's whites                                             | The face rule's face on each page                                                                                                          |
| `--aora-face-soft`    | The features: the `eyes` and `line` faces, brows, and the face of `soft`, `crayon` and `watercolor` | The rule's feature colour on each page, for any colour off the middle                                                                      |
| `--aora-face-pupil`   | A drawn face's pupils                                                                               | Whatever reads on the face                                                                                                                 |
| `--aora-face-glint`   | The light on an eye drawn straight on the body                                                      | Whatever reads on the features                                                                                                             |
| `--aora-face-sticker` | The `sticker` variant's face                                                                        | Paper white, or dark where the white face does not read on the body                                                                        |
| `--aora-hair-shade`   | The shade laid over hair on a filled body                                                           | Black, or white on a body too dark for black to show                                                                                       |
| `--aora-ink2`         | The `riso` variant's second ink                                                                     | A light ink prints over itself; a body of the second ink's own hue (`red`, `pink`, `magenta`) takes gold; the stylesheet default otherwise |
| `--aora-ink-line`     | Lines in the ink: `outline`, `glass`, kaomoji                                                       | Only written where the ink is too faint on a page: deepened on a light page, keeping its hue, and lifted on a dark one                     |
| `--aora-rim`          | The hairline edge of a filled body                                                                  | Only written where the body all but matches a page: its line ink there, `transparent` on the other page                                    |
| `--aora-eye`          | The eyes of the `cute`, `eyes` and `line` faces                                                     | Not written by `getInkVars`: set from `eyeColor`, for eyes in a colour of your own                                                         |

A colour picker's chip shows the colour the body takes on the current page (`getInkColorCss(id)`), so `black`'s turns white on a dark page, and takes the body's hairline edge where it all but matches the page (`--aora-rim`). `CharacterSelector` does both.

```tsx preview
import { getInkVars } from '@aora-bot/engine';

export default function Demo() {
  return (
    <table>
      <tbody>
        {(['blue', 'pink', 'black'] as const).map((id) => (
          <tr key={id}>
            <td>
              <code>getInkVars('{id}')</code>
            </td>
            <td>
              <code>{Object.keys(getInkVars(id)).join(', ')}</code>
            </td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}
```

## Deterministic assignment

Any string maps to a stable colour and shape.

```tsx preview
import { autoColorForKey, autoShapeForKey, renderStaticSvgDataUrl } from '@aora-bot/react';

const keys = ['ada', 'grace', 'alan', 'edsger', 'barbara', 'donald'];

export default function Demo() {
  return (
    <div className="site-demo">
      {keys.map((key) => (
        <div className="site-demo__cell" key={key}>
          <img
            src={renderStaticSvgDataUrl({ shape: autoShapeForKey(key), color: autoColorForKey(key) })}
            width={54}
            height={54}
            alt=""
          />
          <span className="site-demo__label">{key}</span>
          <span className="site-demo__label">{autoColorForKey(key)}</span>
        </div>
      ))}
    </div>
  );
}
```

Assignment uses FNV-1a followed by an avalanche step, so keys that differ by one character land far apart in the pool rather than adjacent to each other. `black` is excluded from assignment — it is reserved as the explicit default, so an assigned character is always visibly "chosen". The assignable colours are a fixed list (`ASSIGNABLE_COLOR_IDS`) that does not grow with the palette, so a new colour never moves an existing key onto another one.

## Halo

`haloBackground` composes a soft multi-stop wash from a hue, for use behind an avatar.

```tsx preview
import { COLOR_IDS, haloBackground, renderAvatarDataUrl } from '@aora-bot/react';

export default function Demo() {
  return (
    <div className="site-demo">
      {COLOR_IDS.slice(0, 6).map((id) => (
        <span
          key={id}
          style={{
            display: 'grid',
            placeItems: 'center',
            width: 74,
            height: 74,
            borderRadius: 18,
            background: haloBackground(id),
          }}
        >
          <img src={renderAvatarDataUrl(id, { color: id })} width={46} height={46} alt="" />
        </span>
      ))}
    </div>
  );
}
```
