# ActivityMark

What an agent is doing, as a character and a label.

```tsx preview
import { MarkStageProvider, ActivityMark, TOOL_ACTIVITIES } from '@aora-bot/react';

export default function Demo() {
  return (
    <MarkStageProvider>
      <div className="site-demo site-demo--column">
        {Object.keys(TOOL_ACTIVITIES).map((tool) => (
          <ActivityMark key={tool} agent={{ id: tool }} tool={tool} />
        ))}
      </div>
    </MarkStageProvider>
  );
}
```

## One source for both halves

The tool name picks an animation state **and** a label at the same time. The state comes from the engine's `stateForTool()` table — the same mapping the Claude Code and Cursor adapters use — so a host that already speaks the [emotion protocol](/design/protocol) and a host that only has a tool name cannot disagree about what the face should show.

```ts
activityFromTool('web_search');
// → { labelKey: 'activity.searching', state: 'searching' }
```

Unknown tools fall back to a generic working state rather than rendering nothing, so a new tool degrades gracefully.

## Adding tools

```ts
import { TOOL_ACTIVITIES } from '@aora-bot/react';

TOOL_ACTIVITIES.deploy = { labelKey: 'activity.running', state: 'working' };
```

## Groups

```tsx preview
import { MarkStageProvider, GroupActivityMark } from '@aora-bot/react';

const members = [{ id: 'ada' }, { id: 'grace' }, { id: 'alan' }];

export default function Demo() {
  return (
    <MarkStageProvider>
      <GroupActivityMark members={members} tool="run" />
    </MarkStageProvider>
  );
}
```

Showing every member at once turns a four-person group into a wall of characters, so the row cycles through them instead — one character wide, while still telling you who is involved.

## Language

Labels come from the [locale provider](/components/locale-provider), so the text follows the surrounding language without a prop.

```tsx preview
import { LocaleProvider, ActivityMark } from '@aora-bot/react';

export default function Demo() {
  return (
    <div className="site-demo site-demo--column">
      <ActivityMark agent={{ id: 'en' }} tool="search" />
      <LocaleProvider locale="zh-CN">
        <ActivityMark agent={{ id: 'zh' }} tool="search" />
      </LocaleProvider>
    </div>
  );
}
```

## Facts instead of a tool name

`activityMode="tool"` is the default: the caller names a tool and both halves of the row follow. `activityMode="facts"` reads the shared [mark commands](/components/mark-commands) registry instead, so a row and the roster avatar for the same agent cannot disagree about what it is doing. `facts` publishes `{ running, composing, activity }` for the agent while the row is mounted — compared by value, so an inline object is fine — and `surface` says where the row is being drawn. A conversation row is `chat`, where composing is the whole point; on an `avatar` surface the same facts resolve to idle, because twenty faces flicking between two states every few hundred milliseconds is noise. The resolution is `characterStateForRoster(facts, surface)` from the engine.

```tsx preview
import { useState } from 'react';
import { MarkStageProvider, ActivityMark, AgentAvatar, useMarkCommand } from '@aora-bot/react';

const agent = { id: 'nova', shape: 'hex', color: 'violet' } as const;

function RosterAvatar() {
  const snapshot = useMarkCommand(agent.id, 'avatar');
  return <AgentAvatar agent={agent} state={snapshot.state} size="lg" />;
}

export default function Demo() {
  const [composing, setComposing] = useState(true);
  return (
    <MarkStageProvider>
      <div className="site-demo site-demo--column">
        <ActivityMark
          agent={agent}
          activityMode="facts"
          facts={{ running: true, composing, activity: 'writing' }}
          surface="chat"
        />
        <div className="site-demo">
          <RosterAvatar />
          <span className="site-demo__label">same facts, avatar surface</span>
        </div>
        <button className="site-btn" onClick={() => setComposing((c) => !c)}>
          composing: {String(composing)}
        </button>
      </div>
    </MarkStageProvider>
  );
}
```

## Label, bubble, visibility

`showLabel` shows the label `always`, only on `hover`, or `never` — and `never` keeps it in the accessibility tree, because the label is the only part of the row a screen reader can use. `bubble` draws the label as a speech bubble rather than bare text, for a row sitting next to the character rather than under it.

`visible={false}` unmounts with the exit animation rather than instantly. Unmounting on the same tick as the flag flips makes the row vanish instead of leave, which reads as a glitch in a conversation that is otherwise continuous.

```tsx preview
import { useState } from 'react';
import { MarkStageProvider, ActivityMark } from '@aora-bot/react';

export default function Demo() {
  const [visible, setVisible] = useState(true);
  return (
    <MarkStageProvider>
      <div className="site-demo site-demo--column">
        <ActivityMark agent={{ id: 'bubble' }} tool="search" bubble />
        <ActivityMark agent={{ id: 'hover' }} tool="read_file" showLabel="hover" />
        <ActivityMark agent={{ id: 'leaving' }} tool="run" visible={visible} />
        <button className="site-btn" onClick={() => setVisible((v) => !v)}>
          {visible ? 'hide the last row' : 'show it again'}
        </button>
      </div>
    </MarkStageProvider>
  );
}
```

## Poking

`onPoke` is called when the character is clicked, and its presence turns the mark into a real button — without it, a click is nothing, because a tab stop per row of a transcript for a flourish a screen-reader user cannot see is not worth it. A poke also goes through the shared commands, so every other mark for the agent reacts; a mirrored mark that cannot move alone hops its wrapper instead.

```tsx preview
import { useState } from 'react';
import { MarkStageProvider, ActivityMark } from '@aora-bot/react';

export default function Demo() {
  const [pokes, setPokes] = useState(0);
  return (
    <MarkStageProvider>
      <div className="site-demo site-demo--column">
        <ActivityMark
          agent={{ id: 'poke', shape: 'star', color: 'yellow' }}
          tool="think"
          onPoke={() => setPokes((n) => n + 1)}
        />
        <span className="site-demo__label">poked {pokes} times</span>
      </div>
    </MarkStageProvider>
  );
}
```

## Presence hooks

Two hooks the component uses are exported for hosts that render their own row.

`useActivityPresence(visible, { exitMs })` returns `{ mounted, leaving }`: `mounted` stays true through the exit animation and `leaving` marks the frames in which to apply the leaving class. The default `exitMs` is `ACTIVITY_EXIT_MS` (140 ms), and drops to zero under reduced motion. The transition is applied during render rather than in an effect, so the exit is on screen for the very frame that hides the row.

`useSpawnEntrance(agentId)` returns `{ isFirst, state }`: `state` is `'spawning'` while the arrival plays and then `null`, so the caller falls back to its real state. Which agents have been introduced is remembered at module level, not in context — a row that unmounts when you scroll past it and remounts when you scroll back should not arrive twice. `resetSpawnEntrances()` forgets every introduction, for tests and session resets.

```tsx preview
import { useState } from 'react';
import { MarkStageProvider, StagedMark, useActivityPresence, useSpawnEntrance } from '@aora-bot/react';

function Row({ id, visible }: { id: string; visible: boolean }) {
  const presence = useActivityPresence(visible);
  const spawn = useSpawnEntrance(id);
  if (!presence.mounted) return null;
  return (
    <span className={`aora-activity${presence.leaving ? ' aora-activity--leaving' : ''}`}>
      <StagedMark shape="pebble" color="green" state={spawn.state ?? 'idle'} sizePx={28} />
      <span className="site-demo__label">
        {spawn.isFirst ? 'first appearance' : 'seen before'}, {presence.leaving ? 'leaving' : 'here'}
      </span>
    </span>
  );
}

export default function Demo() {
  const [visible, setVisible] = useState(true);
  return (
    <MarkStageProvider>
      <div className="site-demo site-demo--column">
        <Row id="presence-demo" visible={visible} />
        <button className="site-btn" onClick={() => setVisible((v) => !v)}>
          toggle
        </button>
      </div>
    </MarkStageProvider>
  );
}
```

## Accessibility

The label is real text, so the state of the agent is readable without seeing the animation. This is the pattern to copy whenever a character carries meaning — see [accessibility](/guide/accessibility).
