# Components

The React layer is deliberately small. Most of the work happens in the engine; these components decide when to animate, when to share an animation, and when not to animate at all.

<ComponentOverview />

## How they relate

Four tiers. The engine knows nothing about React; the core wraps it in components and decides when to share an animation; the agent layer feeds protocol ids into that core; everything else is composed from the two.

<ComponentGraph />

## Choosing a component

**One character, on its own.** `CharacterMark`.

**Many characters, most of them alike.** `CharacterStageProvider` plus `StagedMark`. One engine per distinct shape-and-state pair, mirrors for the rest.

**An avatar for a user or agent.** `AgentPortrait`. It picks between a picture, a group cluster and a character for you, and derives a stable appearance from an id so you do not have to store one.

**An agent that reports what it is doing.** `AgentStateProvider` plus `CharacterMark`. Hooks and a relay speak the [emotion protocol](/design/protocol); the arbiter decides which session the face shows.

**A number next to the face.** `hud` on any character, from a spec the [protocol](/design/protocol#hud) carries; [`HudPlate`](/components/hud-plate) when it needs a title and a value beside it, [`AgentHud`](/components/agent-hud) when the provider should supply both.

**One agent drawn in several places at once.** [Mark commands](/components/mark-commands) — publish facts once, and every roster row, avatar and activity line for that agent follows.

**Letting someone choose or edit an appearance.** `CharacterSelector` in a settings form; [`AgentCharacterSelector`](/components/agent-character-selector) in a dialog; [`CompactCharacterSelector`](/components/compact-character-selector) beside a sign-up form; [`AvatarStudio`](/components/avatar-studio) when a picture is also allowed; [`TemplateDialog`](/components/template-dialog) when the appearance belongs to a template being created.

**A whole scene.** [`RestrictedScene`](/components/restricted-scene) for a dead end, [`BootLoop`](/components/boot-loop) for an indeterminate wait, [`CastLineup`](/components/cast-lineup) for a scripted piece, the [walkthrough](/components/walkthrough) parts for an onboarding flow.

**A painted mascot instead of a generated one.** `SpriteMark`, keyed by the same protocol ids.

**Hundreds, in a virtualised list.** Neither — use `renderAvatarDataUrl` and render images.
